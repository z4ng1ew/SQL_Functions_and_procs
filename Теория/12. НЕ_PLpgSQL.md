## Разница между SQL и PL/pgSQL функциями

Это два разных языка для написания тела функции в PostgreSQL.

### SQL-функция (`LANGUAGE SQL`)

Просто один или несколько SQL-запросов. Ничего больше:

```sql
CREATE FUNCTION fnc_persons_female()
RETURNS TABLE (...) AS
$$
    SELECT id, name, age, gender, address
    FROM person
    WHERE gender = 'female';
$$
LANGUAGE SQL;
```

Нет переменных, нет IF/ELSE, нет циклов, нет BEGIN/END. Только голый SELECT (или INSERT/UPDATE/DELETE).

### PL/pgSQL-функция (`LANGUAGE plpgsql`)

Процедурный язык (PL — Procedural Language, процедурный язык). Есть переменные, условия, циклы — как в обычном языке программирования:

```sql
CREATE FUNCTION fnc_persons_female()
RETURNS TABLE (...) AS
$$
BEGIN                          -- ← блок кода
    IF (some_condition) THEN   -- ← условие
        ...
    END IF;
    RETURN QUERY               -- ← явный возврат результата
        SELECT id, name, age, gender, address
        FROM person
        WHERE gender = 'female';
END;
$$
LANGUAGE plpgsql;
```

### Аналогия на Си

SQL-функция — это как однострочный макрос:
```c
#define SQUARE(x) ((x) * (x))
```

PL/pgSQL-функция — это как полноценная функция с телом:
```c
int square(int x) {
    int result;
    result = x * x;
    return result;
}
```

Результат одинаковый, но второй вариант мощнее — можно добавить условия, циклы, промежуточные переменные.

### Почему задание требует именно SQL

В ex04 достаточно простого SELECT — никакая логика не нужна. SQL-функция проще и быстрее: PostgreSQL может «встроить» (inline — подставить тело функции прямо в вызывающий запрос) её в основной запрос для оптимизации. С PL/pgSQL так нельзя.

В ex06 задание попросит уже PL/pgSQL — потому что там нужны параметры и более сложная логика.
