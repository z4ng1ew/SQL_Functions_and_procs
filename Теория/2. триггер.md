## Триггер (Trigger)

Триггер — это **автоматически срабатывающая процедура**, привязанная к таблице. Она выполняется сама, без твоего вызова, когда в таблице происходит определённое событие: `INSERT`, `UPDATE` или `DELETE`.

Аналогия из жизни: представь сигнализацию на двери. Ты не нажимаешь кнопку «включить сирену» — она **сама** срабатывает, когда дверь открывается. Триггер работает так же: ты делаешь `INSERT INTO person(...)`, и триггер **сам** записывает копию этой строки в таблицу аудита.

### Как устроен триггер в PostgreSQL

Он состоит из **двух объектов**:

**1. Триггерная функция** — описывает *что делать*. Это обычная функция на PL/pgSQL, но с особым возвращаемым типом `RETURNS TRIGGER`. Внутри неё доступны специальные переменные:

- `NEW` — новая строка (доступна при INSERT и UPDATE)
- `OLD` — старая строка (доступна при UPDATE и DELETE)
- `TG_OP` — строка с названием операции: `'INSERT'`, `'UPDATE'` или `'DELETE'`

**2. Сам триггер** — описывает *когда* и *на что* срабатывать. Указывается:

- таблица (`ON person`)
- событие (`AFTER INSERT`, `BEFORE DELETE` и т.д.)
- гранулярность (уровень детализации): `FOR EACH ROW` — для каждой затронутой строки, или `FOR EACH STATEMENT` — один раз на весь запрос
- какую функцию вызвать (`EXECUTE FUNCTION fnc_...`)

### Минимальный пример из твоего проекта

```sql
-- 1) Функция: ЧТО делать
CREATE FUNCTION fnc_trg_person_insert_audit()
RETURNS TRIGGER AS $$
BEGIN
    INSERT INTO person_audit(row_id, name, age, gender, address)
    VALUES (NEW.id, NEW.name, NEW.age, NEW.gender, NEW.address);
    RETURN NULL;
END;
$$ LANGUAGE plpgsql;

-- 2) Триггер: КОГДА делать
CREATE TRIGGER trg_person_insert_audit
AFTER INSERT ON person
FOR EACH ROW
EXECUTE FUNCTION fnc_trg_person_insert_audit();
```

После этого любой `INSERT INTO person(...)` автоматически скопирует данные в `person_audit` — без единой дополнительной строчки в твоём коде.

### BEFORE vs AFTER

- `BEFORE` — срабатывает **до** выполнения операции. Можно изменить данные в `NEW` перед вставкой или вообще отменить операцию.
- `AFTER` — срабатывает **после**. Данные уже записаны, ты просто реагируешь на факт (как в твоём проекте — пишешь в аудит-лог).

### Зачем `RETURN NULL`?

В триггерах типа `AFTER ... FOR EACH ROW` возвращаемое значение игнорируется PostgreSQL, поэтому пишут `RETURN NULL` — просто формальность. А вот в `BEFORE`-триггерах `RETURN NULL` **отменит** операцию, а `RETURN NEW` — разрешит её.
