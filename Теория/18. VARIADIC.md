## VARIADIC — объясняю с нуля

### Начнём с проблемы

Ты хочешь написать функцию, которая находит минимум. Но ты **не знаешь заранее**, сколько чисел передадут:

```sql
-- Иногда 2 числа:
SELECT find_min(10, 5);

-- Иногда 3:
SELECT find_min(10, 5, 3);

-- Иногда 7:
SELECT find_min(10, 5, 3, 99, -1, 42, 7);
```

Без VARIADIC пришлось бы писать **отдельную функцию** для каждого случая:

```sql
CREATE FUNCTION find_min(a NUMERIC, b NUMERIC) ...              -- для 2 чисел
CREATE FUNCTION find_min(a NUMERIC, b NUMERIC, c NUMERIC) ...   -- для 3 чисел
-- и так далее... бесконечно
```

VARIADIC решает эту проблему: **одна функция принимает любое количество аргументов**.

### Что делает VARIADIC

Одно-единственное действие: **собирает перечисленные аргументы в массив**.

```sql
func_minimum(10, -1, 5, 4.4)
             │    │   │   │
             └────┴───┴───┘
                    ↓
            VARIADIC собирает
                    ↓
           arr = [10, -1, 5, 4.4]
```

Всё. Больше он **ничего не делает**. Просто упаковка.

### Аналогия — коробка

Представь почтовое отделение. Ты приносишь яблоки — 3 штуки, или 5, или 20. Работник берёт **коробку**, складывает туда все твои яблоки и передаёт дальше.

```
Ты:       "Вот 10, -1, 5, 4.4"  (просто перечисляешь)
VARIADIC: берёт коробку (массив), кладёт всё внутрь → [10, -1, 5, 4.4]
Функция:  получает коробку и работает с ней
```

Без VARIADIC тебе самому нужно принести коробку:

```sql
-- Без VARIADIC: сам пакуешь в ARRAY
SELECT func_minimum(ARRAY[10, -1, 5, 4.4]);

-- С VARIADIC: просто перечисляешь, упаковка автоматическая
SELECT func_minimum(10, -1, 5, 4.4);
```

### Сравнительная практика

Создай две одинаковые функции — одну с VARIADIC, другую без:

```sql
-- БЕЗ VARIADIC: принимает готовый массив
CREATE OR REPLACE FUNCTION min_without(arr NUMERIC[])
RETURNS NUMERIC AS $$
    SELECT MIN(n) FROM UNNEST(arr) AS t(n);
$$ LANGUAGE SQL;

-- С VARIADIC: принимает перечисление
CREATE OR REPLACE FUNCTION min_with(VARIADIC arr NUMERIC[])
RETURNS NUMERIC AS $$
    SELECT MIN(n) FROM UNNEST(arr) AS t(n);
$$ LANGUAGE SQL;
```

Теперь вызови обе:

```sql
-- Без VARIADIC — ОБЯЗАН передать массив:
SELECT min_without(ARRAY[10, -1, 5]);        -- ОК: -1
SELECT min_without(10, -1, 5);               -- ОШИБКА!

-- С VARIADIC — можно перечислять:
SELECT min_with(10, -1, 5);                  -- ОК: -1
SELECT min_with(10, -1, 5, 4.4, -99, 200);  -- ОК: -99
SELECT min_with(VARIADIC ARRAY[10, -1, 5]);  -- тоже ОК: -1
```

Разница **только в вызове**. Тело функции одинаковое. VARIADIC — это удобство для вызывающего.

### Очистка после экспериментов

```sql
DROP FUNCTION IF EXISTS min_without(NUMERIC[]);
DROP FUNCTION IF EXISTS min_with(VARIADIC NUMERIC[]);
```

### Ответы на твои вопросы

**«Нельзя использовать без функции и массива?»** — Да, верно. VARIADIC существует **только** в параметрах функций и **только** перед параметром-массивом.

**«Много ли таких модификаторов в PostgreSQL?»** — Нет. Для параметров функций есть всего три модификатора:

```sql
CREATE FUNCTION test(
    IN x INTEGER,        -- IN: входной параметр (по умолчанию, можно не писать)
    OUT y INTEGER,       -- OUT: выходной параметр (функция возвращает через него)
    INOUT z INTEGER      -- INOUT: и входной, и выходной одновременно
);
-- И VARIADIC — четвёртый. Всё, больше нет.
```

**«Принимает параметры любых типов одновременно?»** — Нет! Все аргументы должны быть **одного типа**:

```sql
SELECT min_with(10, -1, 5);           -- ОК: все NUMERIC
SELECT min_with(10, 'hello', 5);      -- ОШИБКА: 'hello' не число
```
