## Перегрузка функций (Function Overloading)

Это когда несколько функций имеют **одинаковое имя**, но **разные параметры**. PostgreSQL различает их по типам аргументов.

### Пример в PostgreSQL

```sql
-- Три функции с ОДНИМ именем, но РАЗНЫМИ параметрами:
CREATE FUNCTION calculate(x INTEGER)    ...  -- принимает целое число
CREATE FUNCTION calculate(x VARCHAR)    ...  -- принимает строку
CREATE FUNCTION calculate(x INTEGER, y INTEGER) ... -- принимает два числа
```

При вызове PostgreSQL сам определяет, какую версию запустить:

```sql
SELECT calculate(42);         -- вызовет первую (INTEGER)
SELECT calculate('hello');    -- вызовет вторую (VARCHAR)
SELECT calculate(10, 20);     -- вызовет третью (INTEGER, INTEGER)
```

### Аналогия на Си

В чистом Си перегрузки **нет** — каждая функция должна иметь уникальное имя:

```c
int add_int(int a, int b) { return a + b; }
float add_float(float a, float b) { return a + b; }
```

В C++ перегрузка есть (как в PostgreSQL):

```cpp
int add(int a, int b) { return a + b; }
float add(float a, float b) { return a + b; }
// Компилятор сам выбирает нужную версию по типам аргументов
```

### Почему это важно для DROP FUNCTION

Именно из-за перегрузки при удалении нужно указывать тип параметра:

```sql
-- Допустим, существуют:
CREATE FUNCTION fnc_persons(pgender VARCHAR) ...
CREATE FUNCTION fnc_persons(page INTEGER) ...

-- Какую удалить?
DROP FUNCTION fnc_persons;            -- ОШИБКА: неоднозначно, какую из двух
DROP FUNCTION fnc_persons(VARCHAR);   -- ОК: удалит первую
DROP FUNCTION fnc_persons(INTEGER);   -- ОК: удалит вторую
```

В нашем случае `fnc_persons` одна, но указание `(VARCHAR)` — хорошая привычка на будущее.
