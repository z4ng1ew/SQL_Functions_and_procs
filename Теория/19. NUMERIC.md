
### NUMERIC

Числовой тип данных в PostgreSQL. Может хранить и целые, и дробные числа с произвольной точностью:

```sql
42        -- целое
-1.0      -- дробное
5.555555  -- тоже дробное
```

Аналог в Си — нечто среднее между `int` и `double`, но без потери точности (в отличие от `float`/`double`, которые могут округлять).

### Почему массив `[]`

Квадратные скобки `[]` означают «массив этого типа»:

```sql
NUMERIC     -- одно число:        42
NUMERIC[]   -- массив чисел:      [10.0, -1.0, 5.0, 4.4]
```

Аналог в Си:

```c
double x;         // одно число
double arr[];     // массив чисел
```

VARIADIC **требует** массив — потому что все переданные аргументы нужно куда-то собрать. Массив — это и есть контейнер для них.






























## Разбор строки

```sql
DROP FUNCTION IF EXISTS func_minimum(VARIADIC NUMERIC[]);
```

### Что происходит

Удаляем функцию `func_minimum` из базы данных, если она существует. Всё.

### Зачем `(VARIADIC NUMERIC[])`

PostgreSQL поддерживает перегрузку — может быть несколько функций с одним именем, но разными параметрами:

```sql
func_minimum(VARIADIC NUMERIC[])   -- принимает массив чисел
func_minimum(VARIADIC INTEGER[])   -- принимает массив целых чисел
func_minimum(VARIADIC TEXT[])      -- принимает массив строк
```

Указывая `(VARIADIC NUMERIC[])`, ты говоришь: «удали именно ту, которая принимает массив NUMERIC». Это как адрес — чтобы PostgreSQL не перепутал.

### VARIADIC

Модификатор, означающий «переменное число аргументов». Аналогия: корзина в магазине. Ты можешь положить туда 2 яблока, или 5, или 100 — корзина примет любое количество. Но только яблоки (один тип).

```sql
SELECT func_minimum(10, -1, 5);           -- 3 числа — ОК
SELECT func_minimum(10, -1, 5, 4.4, 99);  -- 5 чисел — тоже ОК
-- PostgreSQL сам собирает все числа в массив
```
