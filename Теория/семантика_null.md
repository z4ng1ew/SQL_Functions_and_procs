## Почему `RETURN NULL` семантически точнее

Семантика (semantics) — это **смысл**, значение кода. Не «что он делает технически», а «что он **сообщает** читающему».

### `RETURN NULL` говорит:

> «Я ничего не возвращаю, потому что возвращаемое значение здесь **не имеет значения**».

Это правда — в AFTER-триггере PostgreSQL действительно игнорирует то, что ты вернул.

### `RETURN OLD` говорит:

> «Я возвращаю старую строку».

Читающий может подумать: «А зачем? Кто-то использует это значение? Может, без этого что-то сломается?» — и начнёт разбираться, хотя на самом деле значение **выбрасывается в никуда**.

### Аналогия на Си

```c
// Функция, результат которой никто не использует:

void process(int x) {   // ← честно: "я ничего не возвращаю"
    printf("%d", x);
}

int process(int x) {    // ← вводит в заблуждение: зачем int,
    printf("%d", x);    //   если возврат никому не нужен?
    return x;
}
```

Оба варианта работают, но `void` **честнее** передаёт намерение. `RETURN NULL` в AFTER-триггере — это аналог `void`: явный сигнал «тут нечего возвращать».
