## Объясняю на примере

### Без inline (PL/pgSQL)

Когда ты вызываешь:

```sql
SELECT func_minimum(VARIADIC arr => ARRAY[10.0, -1.0, 5.0, 4.4]);
```

Если функция на PL/pgSQL, PostgreSQL делает так:

```
1. Выполняет внешний SELECT
2. Видит вызов func_minimum(...)
3. ОСТАНАВЛИВАЕТСЯ
4. Переключается в движок PL/pgSQL
5. Выполняет тело функции как отдельный запрос
6. Получает результат
7. Возвращается обратно во внешний SELECT
8. Подставляет результат
```

Это как вызов функции в Си — переход по адресу, создание нового стекового кадра (stack frame — область памяти для локальных переменных функции), выполнение, возврат. Есть **накладные расходы** (overhead — дополнительные затраты ресурсов) на переключение.

### С inline (SQL-функция)

Если функция на чистом SQL, PostgreSQL может сделать трюк — **подставить тело функции прямо в вызывающий запрос**, как будто функции вообще нет:

```sql
-- Ты написал:
SELECT func_minimum(VARIADIC arr => ARRAY[10.0, -1.0, 5.0, 4.4]);

-- PostgreSQL превращает это в:
SELECT MIN(val) FROM UNNEST(ARRAY[10.0, -1.0, 5.0, 4.4]) AS nums(val);
```

Функция «растворилась» — осталось только её тело. Никакого переключения, никаких накладных расходов. Один запрос, один план выполнения.

### Аналогия на Си

Это **буквально** то же самое, что `inline` в Си:

```c
// Обычная функция — вызов через стек:
int add(int a, int b) { return a + b; }
int result = add(3, 5);

// inline — компилятор подставляет тело:
inline int add(int a, int b) { return a + b; }
int result = 3 + 5;  // ← компилятор заменил вызов на тело
```

В PostgreSQL то же самое, только решает не компилятор, а **планировщик запросов** (query planner — компонент, который выбирает оптимальный способ выполнения запроса).

### Почему PL/pgSQL нельзя встроить

PL/pgSQL — это **другой язык** с переменными, циклами, IF/ELSE. PostgreSQL не может «растворить» процедурный код в SQL-запросе — это разные движки. SQL-функция — это просто SELECT, который легко подставить в другой SELECT.

### Когда это важно

На одном вызове разница незаметна. Но если функция вызывается **миллион раз** (например, в WHERE для каждой строки большой таблицы), накладные расходы PL/pgSQL складываются, и SQL-функция будет ощутимо быстрее.
