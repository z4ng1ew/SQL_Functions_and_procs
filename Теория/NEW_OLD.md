## Объясняю с нуля

Забудь на секунду про NEW и OLD. Представь простую ситуацию.

### Что происходит при UPDATE

В таблице `person` лежит строка:

```
id=10, name='Damir', age=22, gender='male', address='Irkutsk'
```

Ты делаешь:

```sql
UPDATE person SET name = 'Bulat' WHERE id = 10;
```

В момент выполнения UPDATE **существуют два состояния** этой строки:

```
ДО изменения:    id=10, name='Damir',  age=22, gender='male', address='Irkutsk'
ПОСЛЕ изменения: id=10, name='Bulat',  age=22, gender='male', address='Irkutsk'
```

PostgreSQL дал этим двум состояниям имена:

- `OLD` — строка **ДО** изменения (Damir)
- `NEW` — строка **ПОСЛЕ** изменения (Bulat)

Эти два состояния существуют **только в момент работы триггера** — это временные «снимки» строки, которые PostgreSQL создаёт автоматически при каждом UPDATE. После завершения триггера они исчезают.

### Почему мы используем OLD, а не NEW

Вопрос: **что мы хотим сохранить в аудите?**

После UPDATE в таблице `person` уже лежит `name='Bulat'` (новое значение). Его можно посмотреть в любой момент простым SELECT. Оно **никуда не денется**.

А вот `name='Damir'` (старое значение) — **исчезло навсегда**. Таблица `person` его больше не хранит. Если мы не запишем его в аудит прямо сейчас, мы его потеряем.

Поэтому:

```sql
-- Записываем OLD (Damir) — то, что ПРОПАЛО из таблицы:
VALUES (CURRENT_TIMESTAMP, 'U', OLD.id, OLD.name, OLD.age, OLD.gender, OLD.address);
```

### Аналогия

Ты живёшь по адресу «ул. Ленина, 5». Переезжаешь на «ул. Мира, 10».

- `NEW.address` = «ул. Мира, 10» — твой **новый** адрес. Его и так все знают — ты там живёшь.
- `OLD.address` = «ул. Ленина, 5» — твой **старый** адрес. Если не записать, никто не вспомнит.

Аудит — это журнал, куда записывают **старый адрес**, потому что новый и так виден.

### Итого

| Состояние | Что это | Где его взять после UPDATE |
|---|---|---|
| `NEW` (Bulat) | Новые данные | Лежат в таблице `person` — доступны через SELECT |
| `OLD` (Damir) | Старые данные | **Нигде** — пропали навсегда, если не записать в аудит |

Вот почему при UPDATE мы пишем `OLD` в аудит. `NEW` нам тоже **доступен**, но записывать его нет смысла — он и так сохранён в самой таблице `person`.
