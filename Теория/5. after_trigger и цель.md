## AFTER-триггер

Это просто триггер, у которого указано `AFTER`:

```sql
CREATE TRIGGER trg_person_insert_audit
AFTER INSERT ON person    -- ← вот это делает его AFTER-триггером
```

Бывает два вида:

- **AFTER-триггер** — срабатывает **после** операции. Строка уже вставлена/изменена/удалена, ты просто реагируешь на факт.
- **BEFORE-триггер** — срабатывает **до** операции. Можно изменить данные или отменить операцию целиком.

«AFTER-триггер» — это не отдельный термин, а просто сокращённый способ сказать «триггер с типом AFTER».

## Зачем вообще нужен триггер и функция

Твоя интуиция понятна: для одного Дамира это действительно избыточно. Но представь реальную ситуацию.

### Без триггера

У тебя таблица `person` с миллионом клиентов. 50 разработчиков, 10 сервисов, 3 администратора — все могут менять данные. Кто-то случайно удалил клиента. Или кто-то поменял адрес, а потом никто не помнит, какой был старый. Чтобы это отследить, **каждый**, кто пишет INSERT/UPDATE/DELETE в `person`, должен **вручную** дублировать данные в `person_audit`:

```sql
-- Разработчик 1 пишет:
INSERT INTO person(...) VALUES (...);
INSERT INTO person_audit(...) VALUES (...);  -- не забудь!

-- Разработчик 2 пишет:
UPDATE person SET name = 'Булат' WHERE id = 10;
INSERT INTO person_audit(...) VALUES (...);  -- не забудь!

-- Админ через консоль:
DELETE FROM person WHERE id = 10;
-- Забыл записать в аудит... данные потеряны навсегда.
```

Рано или поздно кто-то **забудет** или **не захочет** писать вторую строчку. И аудит потеряет смысл — в нём будут дыры.

### С триггером

Триггер делает запись в аудит **автоматически и принудительно**. Никто не может его обойти — ни разработчик, ни админ, ни внешний сервис:

```sql
-- Любой пользователь просто работает с person:
INSERT INTO person(...) VALUES (...);
-- Всё. Триггер САМ запишет в person_audit. Забыть невозможно.

DELETE FROM person WHERE id = 10;
-- Триггер САМ сохранит старые данные перед удалением.
```

### Аналогия

Представь бухгалтерию. Вариант без триггера — каждый сотрудник должен **сам** записывать в журнал, что он взял из кассы. Вариант с триггером — на кассе стоит камера, которая **автоматически** фиксирует каждую операцию. Камеру нельзя забыть включить, нельзя обойти, нельзя «случайно» не записать.

Это и есть практическая необходимость: **гарантированная** запись всех изменений без участия человека. В задании масштаб маленький (один Дамир), но механизм — тот же, что используется в банках, медицинских системах, государственных реестрах — везде, где важно знать, кто, когда и что изменил.
